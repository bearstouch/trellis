# S031 performance and reliability qualification

Date: 2026-10-16. The qualification tooling, unit and fuzz tests, and a full release-build run are complete, with an independent review. **One requirement misses**: the 10 MiB/s flood throughput (see Blocker), so S031 is not complete.

Measured results, environment, and limitations are in [S031-qualification-results.md](S031-qualification-results.md). That file is generated by `scripts/qualify.py`.

## Tooling

**`scripts/qualify.py`** builds and launches the **release** app directly, without a debugger. Each instance runs on a fresh temporary state directory with `--fixture`, so the user's login shell, workspace, Keychain, and hosts are never touched. It authenticates with a seeded test grant over the real control socket and then:

- **Launch:** times 20 launches, from exec until the control API answers and the startup window exists.
- **Idle cost:** samples app RSS and CPU time over 60 s with 10 idle `cat` panes, reporting child memory separately.
- **Capacity:** builds 10 windows, 50 tabs, and 100 running sessions and checks the counts and that IDs are unique.
- **Switching and echo proxies:**
  - switching is timed as `tab.focus` round trips;
  - echo is timed from `session.sendInput` to the PTY echo arriving in the app.
- **Flood:** runs a paced 10 MiB/s writer for 60 s that records the bytes actually consumed. Meanwhile it times navigation, alternating into the flooding tab, and samples RSS and the journal gap flag.
- **Cleanup:** runs 100 create/close cycles via the API, counting numeric file descriptors and child processes, and checks every spawned PID directly.

`MeasurementSummary` (Core) and the script both use nearest-rank percentiles. Fewer than 20 samples is reported as insufficient, never as a pass.

Cleanup on failure kills leftover session process groups only after verifying the group leader's identity, and removes the temp directories.

## Tests

- `testS031_UT01_randomizedTreeOperationsKeepInvariants`: four seeds × 400 random create, split, delete, reorder, and resize operations. After every step the snapshot validates, IDs are unique across kinds and never change kind, and there are at most 100 panes.
- `testS031_UT02_queuesRespectAllBudgets`: a 64 MiB multi-session flood stays within the 8 MiB journal budget with gaps reported. The scrollback limit is 10,000 lines / 16 MiB, and persisted state over 4 MiB is refused. The event ring and the 1 MiB outbox are covered in S025.
- `testS031_UT03_repeatedCleanupReturnsToBaseline`: 100 real cycles, every tenth a failed launch. Each live cycle asserts a successful start and a new child before closing. Afterwards, 90 spawned PIDs are all gone (`ESRCH`), file descriptors are at or below baseline, and no terminals, windows, or journal bytes remain.
- `testS031_UT04_measurementSummaryCalculatesP95`: exact nearest-rank values, order independence, rejection of 19 samples and of NaN-padded samples, and insufficient data never counting as a pass.
- Boundary fuzzing (NFR-R04), with seeded replay:
  - 3,000 mutations of control frames, layouts, themes, portable files, and a real saved workspace;
  - no crash, every accepted layout plan validates, and every mutated workspace that still decodes validates;
  - nesting and size limits apply before decoding.

Full suite: **303 tests passed, 0 failures**. Lint is clean, the build has zero warnings, and the app packages and verifies.

## Blocker: flood throughput (NFR-P07)

With the flooding pane visible, the app consumes 5–7.6 MiB/s rather than 10 MiB/s. The writer is back-pressured by the PTY, so this is the app's real consumption rate. Navigation stays usable (p95 60 ms) and memory stays bounded.

Likely causes, still to be confirmed with Instruments:

- Every PTY chunk (up to 16 KiB) is handled on the main actor: SwiftTerm parse and render invalidation, scrollback enforcement, search invalidation, the journal append, and the event forwarder.
- Scrollback enforcement and output-change callbacks run per chunk instead of being coalesced per frame.

Remediation plan:

1. Profile with Instruments (Time Profiler) on the release build.
2. Batch PTY reads into larger main-actor deliveries.
3. Enforce scrollback and invalidate search once per display frame.
4. Consider moving parsing off the main actor. This is the S001 engine decision.
5. Re-run `scripts/qualify.py` and update this record.

The story stays open until the measured rate meets 10 MiB/s.

## Independent review

The review fixed five methodology and correctness issues, and re-ran qualification twice with the corrected method:

1. The flood never actually ran at 10 MiB/s: Perl's whole-second `time` was used for pacing. The achieved rate is now measured and reported, and the hard-coded "responsive" flag was removed.
2. Cleanup cycles could pass without starting anything, and re-parented orphans were invisible. Starts are now checked and every spawned PID is verified directly.
3. "Descriptors" had counted non-fd `lsof` rows. The CPU parser mishandled the days form, and the echo loop had no exit.
4. UT03 could pass without a working spawn path.
5. The startup grant-loading fix had a data-loss gap: creating a grant before the store loaded overwrote saved grants. Startup now uses `ensureLoaded`, with a regression test.

The review also made launch timing wait for the startup window and added a real-workspace fuzz seed.

**Found by qualification and fixed:** clients connecting during app startup were rejected and rate-limited because grants loaded asynchronously. Grants now load before the first authentication.

Follow-ups:

- Repeat the idle measurements and record load and window occlusion, because results vary.
- Launches write `app.windowFrame` to the shared "Trellis" defaults domain.
- Fuzz method-level parameter validators.
- Run the reference matrix: other macOS versions, Intel, and displays (S001/S032).
