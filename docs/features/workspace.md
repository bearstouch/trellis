# Spaces, tabs and panes

These are the organizing requirements. All are P0 unless marked. The acceptance check is the observable release behavior that proves each one.

A **space** is an entry in the left sidebar: an ordered set of tabs, each with its own split tree of panes. A space is usually what a [library project](project-library.md) becomes when you launch it: the project's tabs open in it, and you can add **temporary tabs** that are yours for this session of work and never change the project. A space can also stand alone (**New Space**, ⌘N) with no project. Spaces were called *windows* before; the API and CLI still accept the old names for now (see [Methods](../api/methods.md#deprecated-names)). The terminal-bearing macOS window that shows the sidebar is the *native window* (MAC-04).

The dragged space takes the place of the space it's dropped on, so dragging down lands below that space and dragging up lands above it; an accent bar marks where it will land. Dropping a tab or text from another app on a space, or a space on the tab bar, changes nothing. |

## Tabs

| ID | Requirement | Acceptance check |
| --- | --- | --- |
| FR-T01 | Support multiple tabs per space: create, rename inline from the tab bar, reorder, duplicate the configuration, and close. | Double-click a tab label or choose Rename. Enter commits, Escape cancels, and empty input keeps the name. The new name persists without restarting sessions. Duplicating a tab copies its layout and launch settings into new sessions and processes; it copies no output and no shell input. |
| FR-T02 | Show the selected space's own ordered tab bar above its terminal area, and switch tabs by mouse, keyboard or command service. | Switch between two spaces with different tabs; each keeps its own tab order and selection. Every way of selecting a tab focuses the same pane. Tab separators, the new-tab button and rename are visible. |
| FR-T03 | Confirm before closing running sessions, and summarize the affected panes. | Closing a space with three running panes shows a single confirmation covering all three. |
| FR-T04 | Label a tab with one of seven colors (red, orange, yellow, green, blue, purple, gray) from the tab's **Color** context menu, the `tab.update` API method or `trellis tab color`. **None** removes the label. | A labeled tab shows a colored stripe along its top edge, a light tint and a tinted icon, selected or not. VoiceOver reads the color name with the tab position (for example "1 of 3, red label"), and hovering the stripe shows the name, so the label never relies on color alone. The label persists across relaunch, a duplicated tab keeps it, and changing it never restarts sessions. A saved color name that this build doesn't know loads as no label instead of triggering recovery. |
| FR-T05 | Show a busy bar along a tab's top edge while any of its panes is printing output. With shell integration, output at the prompt never counts. Output that arrives within 0.15 s of a keystroke is treated as typing echo and ignored, with or without integration (SSH, other shells). A tab whose agent is working shows the agent's moving top edge instead (FR-AG10), so only one bar ever shows. | Run `sleep 1; seq 1 3000000` in a tab, selected or not: its top edge fills and unfills while output arrives and stops about 0.8 s after it goes quiet. Typing at an idle prompt never shows it. With Reduce Motion on, the bar is static. Hovering shows "Printing output" and VoiceOver reads "output in progress" with the tab, so the cue never relies on motion or color alone. A labeled tab animates in its label color. Without integration, programs that redraw on a timer (`top`, `watch`, a tmux clock over SSH) count as output and keep the bar on. |
| FR-T06 | Label a tab whose running program is waiting for the user, without needing shell integration. A **password prompt** (the PTY has echo off with line editing on, as sudo, ssh and `read -s` do) labels the tab while it lasts, even when the tab is selected. A **bell** (BEL) or a **notification** (OSC 9 text, OSC 777 `notify`, a finished OSC 99 notification) labels the tab only when the pane isn't the focused pane of the selected tab. It clears when that pane is shown and focused, at the shell's next prompt, or when the session exits or restarts. With shell integration, nothing counts while the shell is at its own prompt. Notification text is never stored or logged, and is shown only in a desktop notification (FR-T08). | `sudo -k; sudo true` shows an "Input" capsule on the tab and "Password" in the pane header until the password is entered. `sleep 3; printf '\a'` in tab B while tab A is selected labels tab B; selecting tab B clears it. `printf '\e]9;done\a'`, `printf '\e]777;notify;T;B\a'` and `printf '\e]99;;T\e\\'` behave the same; `printf '\e]9;4;1;50\a'` (progress) doesn't. `vim`, `less` and a Tab-completion bell at the prompt never label a tab. The space list shows a keyboard symbol for spaces with a waiting pane. Hovering the capsule shows "Waiting for a password" or "Waiting for input"; VoiceOver reads it with the tab, pane and space, so the cue never relies on color alone. `session.get` reports `waitingForInput: "password"\|"attention"`. |
| FR-T07 | **Settings → Appearance → Bell** chooses what a bell (BEL) does in a pane: **Sound** (the macOS alert sound, the default), **Visual flash**, **Sound and flash** or **Off**. The choice is saved with the appearance settings and applies to every pane without restarting sessions. Whatever the choice, a bell still labels the tab as waiting for input (FR-T06). | Run `printf '\a'`: Sound plays the system alert, Visual flash flashes the pane without sound, Sound and flash does both, Off does neither. With Off, `sleep 3; printf '\a'` in an unselected tab still shows the "Input" capsule. Relaunch and confirm the choice is kept; settings saved before this option existed load as Sound. |
| FR-T08 | Show a **desktop notification** in Notification Center when a program asks for one: OSC 9 text (iTerm2; the pane's title is the notification title), OSC 777 `notify;title;body` (rxvt-unicode) or OSC 99 (kitty: `d=0` chunks, `p=title`/`body`, base64 `e=1`, the `o=always\|unfocused\|invisible` occasion, and a `p=?` query that's answered with what Trellis supports; icons, buttons and close requests are ignored). By default a notification shows only when the user isn't looking at the pane: Trellis isn't the key window, or the pane isn't the focused pane of the selected tab. OSC 99 without `o=` follows this default too (kitty's own default is `always`); `o=always` also shows it in view, and `o=invisible` only when the pane isn't on screen (another tab, behind a maximized pane, or the window hidden, minimized or covered). Nothing shows while the shell (with integration) is at its own prompt. Text is untrusted output: control and bidi-override characters become spaces, the title is capped at 256 characters and the body at 1024, and each pane may post at most 5 notifications per 10 s. Every notification's subtitle says where it came from: "Space › Tab" (the tab's shown title), followed by " · " and the agent or running program's name when Trellis knows it and neither the notification's title nor the tab's automatic title (FR-SI05) already names it; never a command line or its arguments. Space, tab and program names get the same control and bidi cleaning. Clicking a notification brings Trellis forward and selects the pane's space, tab and pane. **Settings → Sessions → Desktop notifications** (on by default, saved with the appearance settings) turns them off; the tab's attention label (FR-T06) still shows. macOS asks for permission on the first notification. Only bundled app builds can post; `swift run` builds can't. With shell integration, a long command finishing out of view also notifies (FR-SI08, in [Shell integration](shell-integration.md)); the toggle turns that off too. | Run `sleep 3; printf '\e]9;Build done\a'` and switch to another app: a notification titled with the pane's title reads "Build done"; clicking it shows that pane. In space *api*, tab *Build*, `make` running `printf '\e]9;Done\a'` shows the subtitle "api › Build · make". With the pane focused and Trellis in front, nothing appears. `printf '\e]777;notify;Claude;Needs approval\a'` in a background tab shows "Claude" / "Needs approval". `printf '\e]99;i=1:d=0;Tests\e\\'; printf '\e]99;i=1:p=body;All passed\e\\'` shows one notification. `printf '\e]99;o=always;Hi\e\\'` shows even in view. A loop of 20 notifications shows 5. With the setting off, none appear but a background tab still gets the "Input" capsule. Relaunch: the choice is kept; settings saved before this option existed load with notifications on. |
| FR-T09 | Show a program's **progress** (ConEmu/Windows Terminal OSC 9;4: `9;4;1;N` set N%, `9;4;2[;N]` error, `9;4;3` indeterminate, `9;4;4[;N]` paused, `9;4;0` remove) on its tab and pane. The tab's top edge fills to the percentage, ahead of a working agent's top edge (FR-AG10), the busy bar (FR-T05) and the color label stripe. An error fills red and a pause orange; an indeterminate report sweeps, and is a static full bar with Reduce Motion on. An error or pause without a value keeps the last one; a pause with none shows 100%. The state is always given in text as well as color: the tab and the pane header show "50%", "Paused 50%", "Error" or "Working". With several reporting panes, the tab shows the most urgent: an error, then a pause, then the lowest percentage, then indeterminate. Progress clears on remove, after 15 s without an update, at the shell's next prompt (with integration), and when the session exits or restarts. It is runtime-only, never persisted, and never labels the tab as waiting for input (FR-T06). Trellis draws it itself; the engine's own progress bar is not shown. | `printf '\e]9;4;1;50\a'` in a background tab: its top edge is half filled and the tab reads "50%"; the pane header reads the same. `printf '\e]9;4;2\a'` turns it red and reads "Error", `printf '\e]9;4;4\a'` orange "Paused 50%", `printf '\e]9;4;3\a'` sweeps and reads "Working" (static with Reduce Motion), and `printf '\e]9;4;0\a'` removes it. Without a further report it clears after 15 s. A new prompt, `exit` or Restart clears it. No "Input" capsule appears. Hovering the bar shows the state; VoiceOver reads it with the tab ("progress 50 percent") and the terminal pane, so it never relies on color alone. The collapsed rail's hover card lists the same text. `session.get` reports `progress: {state, percent?}`. |
| FR-T10 | Reorder tabs by dragging them along the tab bar. The dragged tab takes the place of the tab it's dropped on, so dragging right lands after that tab and dragging left lands before it; an accent bar marks where it will land. Reordering goes through the command service like **Move Left**/**Move Right**, never restarts sessions, and keeps the selected tab. Dragging is off while a tab is being renamed. VoiceOver offers **Move Left** and **Move Right** actions on each tab. | With tabs A, B, C, drag A onto C: the order is B, C, A and every session keeps running. Drag A onto B: the order is A, B, C. While dragging, the bar shows on C's trailing edge (or B's leading edge). Relaunch and confirm the order is kept. Dropping a tab outside the tab bar, or dropping text from another app on a tab, changes nothing. Double-click to rename and drag inside the field: it selects text instead of moving the tab. |

## Panes and splits

| ID | Requirement | Acceptance check |
| --- | --- | --- |
| FR-P01 | Split any pane left/right (`x`) or top/bottom (`y`), including nested splits. | Build a three-pane mixed-axis layout and verify each pane works on its own. |
| FR-P02 | Resize splits with draggable dividers and keyboard controls. | Ratios persist. Neither child can go below 20 columns × 5 rows. An invalid split returns a clear error. |
| FR-P03 | Collapse the parent branch when a pane closes. | Closing one leaf leaves its sibling filling the parent's region, and the remaining IDs don't change. Closing a tab's last pane closes the tab, and closing a space's last tab closes the space. |
| FR-P04 | Navigate panes by direction and temporarily maximize one. | Maximize and restore keep the tree and ratios intact, and focus indicators stay visible. |
| FR-P05 | Show which pane has focus when a tab shows more than one pane. The focused pane's header gets a 3-point `ui.focusRing` line along its bottom edge, an accent tint and a title in the foreground color; other headers use `ui.background` (with the native themes this usually looks the same as an ordinary header), and their terminal content is dimmed by 18% toward the terminal background. An open find bar isn't dimmed. | Moving focus between split panes moves all of these, and the terminal grid never resizes. A tab with one visible pane, including a maximized pane, looks as it did before. With the window inactive or Increase Contrast on, nothing is dimmed but the header cues stay. Reduce Motion removes the dim's fade. Clicks, selection and scrolling still reach a dimmed terminal, and a stopped pane's buttons aren't dimmed. A theme's tint is reduced, or dropped, whenever it would take header text below 4.5:1 or the line, accent and warning colors below 3:1; the line and title remain. |

Limits: split ratios are finite and between 0.1 and 0.9, nesting is at most 16 levels deep, and a workspace holds at most 100 panes. A mutation that fails never leaves a partial tree behind.

## Persistence and portability

| ID | Requirement | Acceptance check |
| --- | --- | --- |
| FR-R01 | Save and restore the organization as stopped panes. | After a normal quit and relaunch, names and splits come back without running any command. The only sessions that come back running are ones the broker kept (FR-R03, FR-R07), which is the default; nothing is ever started or replayed by a restore. |
| FR-R02 | Import and export the project library and saved-host metadata, with a review summary. Spaces are not exported: they are what projects become once loaded. | **File → Export Projects & Hosts…** writes every project (without its identity or the folders it was launched in, FR-PL05) and every saved host (without IDs, passwords or revisions) as a `trellis.portable` version 2 file. **File → Import Projects & Hosts…** validates the whole file before changing anything and shows the number of projects and hosts, host collisions (which need an explicit choice), and projects named like one you have (added as copies named "… (imported)", never over yours). Everything gets fresh IDs; nothing opens or starts. A version 1 file (from before spaces, which also carried windows) is still accepted: its hosts and projects are imported, and the review says its windows are not. Unsupported versions are refused, and a failure (for example the project library can't be written) removes the hosts already staged, so nothing is half-imported. |
| FR-R03 | Keep sessions running after quit, and reconnect them at the next launch, unless the user chooses otherwise. | Sessions run in the bundled `trellis-broker` helper (FR-R07). **Settings → Sessions → Stop sessions when Trellis quits** is off by default. With it off, ⌘Q sends no signal and quits without asking when every running session is in the broker; if some aren't (the broker couldn't start), it offers **Keep Running** (default), **Stop Sessions** and **Cancel**, saying how many will stop. With it on, ⌘Q asks the usual running-session confirmation and ends every session. On relaunch each kept session returns to its pane, matched by session UUID, running, after a replay of up to 4 MiB of its output. A session that ended meanwhile comes back stopped with its replay and "— Session ended while Trellis was closed (exit N) —", provided the broker is still running: it exits 30 s after its last running session ends with no app connected, and the replay of ended sessions goes with it. A kept session no restored pane claims raises **Stop Them** (SIGHUP) / **Leave Running**; nothing is ended silently. Closing the native window hides it and sessions keep running; with Stop sessions when Trellis quits on, it ends them (MAC-04). A settings file from before this default (which saved `keepSessionsRunning`) adopts it, and if quitting used to stop its sessions, Settings says so once. |
| FR-R07 | Run every session in the broker, so a crash or force quit doesn't end it. | Whatever the quit setting, local and SSH-pane sessions are started through `trellis-broker`. Kill the app with `kill -9` while `sleep 600` and a full-screen program (for example `vim`, `htop` or Claude Code) run: `ps` still shows them, and on relaunch they return to their panes running, with their replay, and the full-screen program redraws. If the broker can't start, the session runs as an ordinary PTY and the app says it will end when Trellis quits. |
| FR-R04 | Optionally restore each pane's scrollback after quit, as plain text. | **Settings → Sessions → Restore scrollback after quit**, off by default; its caption says the file is unencrypted and redaction is best effort. On quit each pane's retained text is redacted (FR-R05) and saved to `Scrollback/<session-uuid>.txt` (at most 1 MiB per pane, 64 MiB in all, mode `0600` in a `0700` folder, written atomically). On restore it is shown in the stopped pane, cleaned to text only, followed by "— Restored output from <date> —". The file is deleted when the pane or space closes, the pane restarts, the setting is turned off, or its session isn't in the saved workspace. It is never exported, imported or journaled. A pane adopted under FR-R03 shows the broker replay instead, and its file is deleted. |
| FR-R05 | Remove credentials from saved scrollback, on a best-effort basis. | Before writing, PEM private keys (and bare 64-column base64 lines), `Authorization:` values, `Bearer` tokens, `scheme://user:password@` credentials, `password`/`passwd`/`passphrase`/`secret`/`token`/`api_key`/`access_key`/`client_secret`/`private_key` assignments (env lines, YAML, JSON, `--flag value` and `--flag=value`), AWS (`AKIA…`, `ASIA…`), GitHub (`gh[pousr]_`, `github_pat_`), GitLab `glpat-`, Slack `xox?-`, `sk-`/`sk-ant-`, Stripe `sk_live_`/`rk_live_`, Google `AIza…`, npm `npm_`, JWTs, and text typed after a `password:` prompt on the same line become `[redacted]`. Ordinary output (for example "The token is valid", "password reset complete") is unchanged. Redaction can miss secrets in other formats. |
| FR-R06 | Keep the workspace file's disk writes within a budget. | `workspace.json` is rewritten only when its content changes; a save with nothing new writes nothing, not even the backup. **Settings → Sessions → Workspace disk writes** sets how much the file and its backup may write per hour: 10, 25, 50 (default), 100 or 250 MB, saved per state directory; an unknown value reads as the default. Past the budget, ordinary changes are saved together once every 5 minutes instead of 300 ms after each change, and the caption says so; ⌘S and Quit still save at once, and raising the budget ends the batching. Check that saving an unchanged workspace leaves the file's modification date alone, that a spent budget saves two quick changes in one write after the interval, and that ⌘S during batching writes immediately. |

**File → Export Projects & Hosts…** and **File → Import Projects & Hosts…** implement FR-R02. FR-R03 is described in [Sessions](../architecture/sessions.md#session-broker), and the files of FR-R04 in [Persistence](../architecture/persistence.md#opt-in-scrollback-file). The rules for portable documents are in [Integrations](../integrations.md#configuration-import-and-export), and the on-disk format is described in [Persistence](../architecture/persistence.md).

## Closing the native window

Closing the terminal-bearing native window hides it; sessions keep running and the Dock icon brings it back. With **Stop sessions when Trellis quits** on, closing it while sessions are live asks once whether to end them instead. If you accept, the sessions end and the window hides, but spaces, tabs and splits stay as stopped panes and remain saved, so a later Quit and relaunch restores them (FR-R01). Reopening the main window shows the same layout with stopped panes. Quitting has its own running-session confirmation. See [macOS support](../platform/macos.md) (`MAC-04`).
