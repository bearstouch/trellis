# Project library

A project is a workspace you define once in Trellis and launch whenever you need it, on this Mac or on any saved SSH host: its tabs, splits and panes, the folder and command of each pane, and the git repositories it's made of. Projects live in Trellis's own settings, not in a repository, so the same definition sets up a laptop, a build server or a fresh VM.

**Projects** at the bottom of the sidebar (and **File → Projects…**, ⌘O) opens the library. Launching asks where the project runs and in which folder, shows what will happen there, clones what's missing, and opens the workspace window.

All requirements here are P1. They replace the repository project files (`.trellis/project.json`, FR-WF01–FR-WF08) of earlier builds; those files are no longer read. Tasks (`.trellis/launch.json`, [Tasks](tasks.md)) are unchanged.

## A project

| Element | Rules |
| --- | --- |
| Project | `name` (1–200 characters), optional `notes`, an optional `repository` (the project folder itself is a checkout of it) and 1–50 `tabs`. |
| Tab | `title` (1–200 characters), optional `color` (`red`, `orange`, `yellow`, `green`, `blue`, `purple`, `gray`), an optional `repository` with a `directory`, and a `root` node. Panes in the tab without a `directory` start in its repository's folder. |
| Pane | Optional `title`, `directory`, `command`, `agent` and `repository`. A pane's `repository` makes its `directory` (required then) a checkout. `agent` (FR-PL10) and `command` exclude each other. |
| Split | `axis` `x` or `y`, `ratio` 0.1–0.9 (the first child's share) and exactly two children. |
| `directory` | Relative to the project folder chosen at launch. Omitted or `.` means the project folder. Absolute paths, `~`, `..` segments, `$`, backticks, quotes and backslashes are rejected. |
| `command` | One line of at most 4,096 characters, typed into the pane's login shell after its first prompt. Control, line-separator and invisible characters are rejected. |
| `agent` | An agent ID from Settings → Agents, such as `trellis-claude-code`, `trellis-pi` or `trellis-codex`: lower-case letters, digits and `-`. The pane opens as that agent instead of a shell. |
| `repository` | `url`: `https://…`, `ssh://…` or `user@host:path`, at most 2,048 characters of letters, digits and `-._~:/@%+=,`, never starting with `-`; other transports (`file://`, `ext::`, `http://`) are rejected. Optional `branch`, following git's branch-name rules. Two repositories may name the same folder only with the same `url` and `branch`. |

Limits are those of layouts: at most 50 tabs, 100 panes and 16 levels of nesting. The JSON form is the same structure, `{"name", "notes", "repository", "tabs": [{"title", "color", "directory", "repository", "root": {"type": "pane"|"split", …}}]}`.

## Requirements

| ID | Requirement | Acceptance check |
| --- | --- | --- |
| FR-PL01 | Open the project library from the sidebar. The sidebar's bottom bar shows **Projects** above Hosts and Settings (an icon with the same label in the collapsed rail), and **File → Projects…** (⌘O, rebindable in Settings → Keyboard) opens it. It is its own window, like Hosts: a searchable list of projects on the left, the selected project's editor on the right. | Clicking **Projects**, choosing the menu item or pressing ⌘O shows the window, and again brings the same window forward. The list shows each project's name, its tab and repository counts and where it was last launched; search matches names, notes and repository URLs. VoiceOver reads the button as "Projects" and each row's name and summary. A shortcut saved for the former **Open Project…** keeps working for **Projects…**. |
| FR-PL02 | Edit a project in a form. The editor has the project's name, notes and repository, and an outline of its layout: tabs, splits and panes. Selecting a tab edits its title, color and repository; selecting a pane edits its title, folder, command and repository. **Add Tab**, **Split Right**, **Split Down** and **Remove** change the outline, and **Move Up** and **Move Down** reorder tabs. **Save** stores the project; **Delete…** asks first. | A new project starts with one tab and one pane. Splitting a pane puts it and a new pane in a split; removing one side of a split leaves the other in its place; the last tab and the last pane can't be removed. Every field is checked as you type, with the problem next to it, and **Save** stays disabled while any remains. A pane repository without a folder, or two repositories on one folder with different URLs, is reported. Closing the window, selecting another project, or capturing or importing one with unsaved changes asks to save or discard. Two windows can't overwrite each other's changes: a save after the stored project changed elsewhere is refused and says so. |
| FR-PL03 | Edit a project as JSON. The editor's **Form / JSON** switch shows the project as JSON in the terminal's font and theme, with **Validate** (⌥⌘V) and **Save** (⌥⌘S). | The JSON is the form's project, in a fixed field order with two-space indentation. **Validate** applies the same rules as the form and lists each problem with its tab or pane. Text that doesn't validate can't be saved or switched back to the form; valid text switches back showing the same project. Unknown fields are errors. |
| FR-PL04 | Create projects from a window or a file, and export one to a file. **New from Window…** captures an open sidebar window; **Import JSON…** reads a project in the library's JSON form, which **Export JSON…** writes for the selected saved project (without its identity or the folders it was launched in, and without unsaved edits). Both open the result in the editor, unsaved. | Capturing a window copies its tabs, titles, colors, splits and ratios. The project folder becomes the panes' nearest common folder, remembered as the last folder for the window's target, and each pane's folder becomes relative to it; when that common folder is `/` or the home folder, nothing is remembered and a warning says launching will ask where the project goes. SSH panes and panes running another program become shells, with a warning. Commands are never captured. A captured remote-workspace window uses its folders on the host. An imported file that doesn't validate is refused with its problems, and an imported project gets a new identity, so importing twice gives two projects. |
| FR-PL05 | Keep the library in Trellis's state. Projects are stored in `projects.json` in the state directory, owner-only, written atomically with a backup, and carried by **Export/Import Windows & Hosts** (FR-R02). | `projects.json` is `0600` in a `0700` folder, and contains no terminal output, environment values or secrets (a repository URL with a password in it is refused). An unreadable or newer file opens the library read-only with **Reset Project Library**, which moves the file aside; it is never overwritten. An export includes the library in its JSON form, without identities or the folders each project was launched in; the import preview counts the projects, and **Import** adds them under new identities after the windows and hosts. A project the library would refuse makes the whole file fail before anything is imported. An export with an empty library has no `projects` field; one with projects is refused, as unsupported, by Trellis builds older than the project library. |
| FR-PL06 | Launch a project on a chosen target. **Launch…** asks for the target, **This Mac** or a saved host, and the project folder there: on this Mac an absolute path, on a host a path relative to its home. Both are prefilled from the last launch to that target, else `~/<name>` with the name in lower case and spaces as `-`. Trellis then checks the target and lists what will happen. | The sheet lists, for the chosen target: whether the folder exists or will be created; each repository already cloned (a folder with `.git`, used as it is), each one that will be cloned, and each folder that exists without being a checkout (a warning; it is never touched); and the tabs, panes and commands that will open. Checking a host connects to it first (FR-RW01), so a host-key or password prompt appears in its console. Changing the target or folder checks again. **Cancel** changes nothing anywhere. |
| FR-PL07 | Set up what's missing in a terminal on the target. When the folder or a repository is missing, **Set Up & Open** shows **Setting Up**, a terminal running on the target that creates the folder and clones each missing repository with that machine's git and credentials, then opens the workspace. | The terminal shows git's output and its questions (host keys, passphrases, passwords), which you answer there; Trellis stores and types no credentials. When every step succeeds the sheet closes and the window opens. A failure keeps the sheet with the output and **Retry** (which skips what is already in place), **Open Anyway** (panes in a missing folder fail to start, as they would otherwise) and **Cancel** (what was already cloned stays). A project repository whose folder already has files is initialized in place (`git init`, the remote, a fetch and a checkout of the branch or the remote's default), and git refuses to overwrite a file that is already there. On a host the setup runs in its login shell through the helper (FR-RW18). Nothing runs before you choose **Set Up & Open**. |
| FR-PL08 | Open the project's window and run its commands once. The window is named after the project; on a host it is bound to that host like a remote workspace (FR-RW01), with each pane a shell there. Each command is typed at its new shell's first prompt. Launching the same project on the same target and folder again selects its window and reconciles it. | The first launch creates the window with the project's tabs, colors, splits, pane titles and folders, selects it and starts its shells; each command runs once, and the shell stays when it ends. Launching again adds new tabs and panes, applies changed titles, colors and ratios, removes nothing, restarts nothing and runs no command again. The same project on another target or folder opens another window. Without shell integration a command is written as soon as the shell starts. Commands are never logged or saved with the workspace, and a restored workspace never runs them again. **Launch Project…** in the command palette picks a project and opens the launch sheet. |
| FR-PL09 | Show git status in pane headers. For a local or remote-workspace shell whose directory is inside a git work tree, the pane header shows the branch (or the short commit when detached), "●" and a count when there are uncommitted changes, and "↑n" / "↓n" ahead of and behind its upstream. It needs shell integration, which reports the prompts. | `cd` into a checkout and the header shows its branch; edit a file and the next prompt shows "●1"; commit and "↑1" appears. Status is looked at each time the shell shows its prompt (after a `cd` or a command), never on a timer, with at most one check per pane at a time and a 2 s limit for each git run (two per check: listing filter drivers, then status); a check asked for while one runs follows it. A host whose helper predates protocol 3 shows no status. VoiceOver reads "Git branch main, 1 change, 1 ahead". SSH panes and folders outside a work tree show nothing. Git runs as `git --no-optional-locks -c core.fsmonitor=false -c core.hooksPath=/dev/null -c protocol.allow=never status --porcelain=v2 --branch` with `GIT_NO_LAZY_FETCH=1`, never through a shell, so a repository's settings start no fsmonitor, hook or fetch; every filter driver the repository configures is first listed (`git config -z --name-only --get-regexp '^filter\.'`, which runs nothing) and blanked with `-c filter.<name>.clean=` (and `.smudge`, `.process`, `.required=false`), so re-hashing a changed file runs no clean filter, and a driver name `-c` can't carry means no status rather than a running filter; on a Mac without the developer tools, `/usr/bin/git` is skipped rather than prompting to install them; on a host the helper runs it and returns only the branch and counts. File names are never shown or stored. |
| FR-PL10 | Run a coding agent in a project pane. A pane's `agent` names an agent from Settings → Agents ([Coding agents](agents.md)); in the editor, **Runs** chooses **Shell** or an agent, and an ID the catalog no longer has stays listed as missing. | A pane with `agent` opens as that agent's pane (FR-AG04) in the pane's folder, on this Mac or the project's host, with its icon, live state, Resume and install offer; the other panes stay shells. A pane with both `agent` and `command`, or an `agent` that isn't an agent ID, is refused with the field named. No command is typed into an agent pane. An agent missing from the catalog still opens its pane, which says so when it starts. **New from Window…** keeps an agent pane as one. A library with an agent pane is saved as schema 2, so an older Trellis opens it read-only instead of dropping the agent; one without is still written as 1. |

## Trust and safety

- You write a project's commands and repositories yourself, in Trellis, so launching runs them without a review. An imported project opens in the editor, unsaved, so you see its commands and repositories before saving or launching it.
- Commands run in the target's login shell with your permissions there, like anything you type.
- Git runs with the target's own configuration and credentials. Trellis never stores, reads or types a token, key or password for it.
- Setup only creates folders and clones into folders that don't exist yet, or initializes the project folder in place; it never deletes, resets or overwrites files. When initializing in place fails or is cancelled, it removes only the `.git` it just created, so the folder is as it was and **Retry** starts that step again.
