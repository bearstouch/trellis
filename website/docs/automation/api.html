Automation API

Trellis has a local API so scripts and coding agents can do what you do: build layouts, start sessions, send input and read output. Every client needs a grant you create, and it can only do what that grant allows.

What it is

  • Local only. The API is JSON-RPC 2.0 over a Unix socket that only your macOS user can open. Nothing listens on the network unless you turn on the MCP server.
  • Same rules as the UI. Every call goes through the same path as your clicks, so the API can't do anything the app wouldn't let you do.
  • Three ways in. The trellis CLI for shell scripts, the socket directly for your own clients, and the optional MCP server for agents.

Trellis embeds no AI model and needs no provider API key. It never treats terminal output as instructions.

Create a grant

  1. Open Settings → Automation and choose New Grant….
  2. Name it, for example "Build agent".
  3. Turn on only the capabilities it needs (see below).
  4. Choose which spaces and saved hosts it may use, or All spaces and All saved hosts.
  5. Pick an expiry: 1 hour, 1 day (default), 7, 30 or 90 days.
  6. Choose Create Grant, then Copy Token. The token is shown only this once.

Store the token in an owner-only file, or let the CLI read it from the Keychain with --keychain-grant GRANT_UUID. Trellis keeps only a hash of it on disk.

Revoke… ends a grant immediately: its connected clients are disconnected and the token stops working.

Warning

Grants protect against other clients, not against malware running as your user, which could read your files or the Keychain. Only grant access to software you trust.

Capabilities

CapabilityLets a client
metadata.readList the spaces, tabs, panes and sessions it can see, and their states
layout.writeCreate, rename, reorder, split, resize and focus; apply layouts
session.startStart a stopped pane with its shell or an approved saved host
session.inputType into a session. This is as powerful as running commands in that pane.
session.executeRun commands or arbitrary programs; set their directory and environment
session.output.readRead the screen, scrollback and live output
session.closeEnd sessions and close things that hold running sessions
theme.readRead installed themes and appearance settings
theme.writeImport, replace and delete themes and change appearance
host.readRead saved host details
host.writeCreate, update and delete saved hosts (changing where one connects also needs session.execute)

There is no clipboard access for clients.

Scope

  • Spaces: all, or a chosen set. Tabs and panes created inside a chosen space inherit its scope.
  • All spaces is required to create or reorder spaces, apply layouts, or change themes.
  • Hosts: all, or a chosen set. If you change a host's destination, user, port or identity file, you must approve it again with Reapprove.
  • Anything outside a grant's scope looks to the client as if it doesn't exist.

The socket

When Trellis starts, it writes control.json to its data folder, ~/Library/Application Support/com.bearstouch.trellis/. It names the socket path, a private folder in your temporary directory, and contains no token.

  • Each message is one JSON object on one line, up to 1 MiB.
  • The first request on a connection must be auth.authenticate with the token.
  • Only processes running as your user can connect. Failed logins are rate-limited.
{"jsonrpc":"2.0","id":1,"method":"auth.authenticate","params":{"protocolVersion":1,"token":"trl_…"}}

Most people never touch the socket directly; the CLI does all of this for you:

$ trellis space list --token-stdin --json < ~/.config/trellis/token

The API calls them spaces too (space.list, spaceId). Older window.* names still work as deprecated aliases.

Apply a layout

A layout is a JSON document describing spaces, tabs and splits. It's data, not shell code: it can't contain commands, and applying one never runs anything on its own.

{
  "version": 2,
  "spaces": [{
    "key": "project", "name": "Project",
    "tabs": [{
      "key": "development", "title": "Development",
      "root": {
        "type": "split", "key": "main-split", "axis": "x", "ratio": 0.6,
        "children": [
          {"type": "pane", "key": "editor", "title": "Editor", "launch": {"kind": "shell", "directory": "~"}},
          {"type": "pane", "key": "server", "title": "Server", "launch": {"kind": "shell", "directory": "~"}}
        ]
      }
    }]
  }]
}

A pane launches either a shell in a directory (~ or an absolute path) or a saved host ({"kind": "host", "hostId": "…"}). Apply it in three steps:

$ trellis layout validate ./project-layout.json --json
$ trellis layout plan ./project-layout.json --namespace project --json
$ trellis layout apply ./project-layout.json --namespace project --expected-revision 12 --json
  1. Validate checks the document and changes nothing.
  2. Plan shows what would change and gives a baseRevision.
  3. Apply takes that revision as --expected-revision. If the workspace changed in between, it fails with CONFLICT and you plan again.
  • Applying the same document again matches what's already there by key, so you get the same spaces and panes, not duplicates.
  • Apply only adds and updates. Nothing you left out is deleted.
  • New panes start stopped. Pass --start-new to start only the panes this apply created.
  • layout export turns existing spaces into a layout document.

For layouts you open yourself, with commands and repositories, use Projects instead.

Output and events

  • A client with session.output.read can read a session's visible screen, its scrollback, or a stream of raw output.
  • Clients can subscribe to changes in spaces and tabs, selection, session state and exits, appearance, and output.
  • Recent output is kept in memory only, never on disk. A slow client may miss events and is told so, so it can list things again.

Warning

Terminal output is untrusted data. Text on screen that asks an agent to do something grants nothing.
