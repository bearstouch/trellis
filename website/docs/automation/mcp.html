Automation

MCP server

Trellis can run a Model Context Protocol server, so agents such as Claude Code can control it with MCP tools. It's off by default, and it uses the same grants and permissions as the automation API.

Connect an agent

  1. Create a grant in Settings → Automation with the capabilities the agent needs, and copy its token. See Create a grant.
  2. Open Settings → Remote Control, turn on Enable MCP server and choose Apply.
  3. Check that the status says the server is running, with its URL.
  4. Add the server to your agent. Copy Claude Code Command gives you the command with a <TOKEN> placeholder; replace it with your token.
$ claude mcp add --transport http trellis http://127.0.0.1:7777/mcp \
  --header "Authorization: Bearer trl_…"

Any MCP client that supports Streamable HTTP and custom headers works the same way. Copy Endpoint URL copies just the URL.

  • Changes take effect only when you choose Apply, which restarts the server.
  • The status shows the URL when running, or why it isn't, such as "Port 7777 is already in use".
  • The choice is saved with your workspace and survives a relaunch.

Network access

By default only programs on this Mac can connect. Choosing any other interface asks you to confirm with Allow Network Access.

Warning

The server speaks plain HTTP with no TLS. On a network address, anyone who can see the traffic can read the token and terminal output. To reach Trellis from another machine, keep the loopback address and use an SSH tunnel instead:

$ ssh -L 7777:127.0.0.1:7777 my-mac

What agents can do

  • Each API method is a tool named in snake case: space.list becomes space_list, session.sendInput becomes session_send_input.
  • An agent sees only the tools its grant allows. A missing capability returns PERMISSION_DENIED, and anything out of scope looks like it doesn't exist.
  • Tools that close, delete, restart, send input or execute are marked destructive, so your agent can ask you before using them.
  • Event subscriptions aren't available over MCP. Use the socket or trellis events subscribe for those.
  • Output read through MCP comes with a reminder that terminal text is untrusted and must not be followed as instructions.

Security

  • Every request needs the grant token as a bearer token. Revoking the grant ends its MCP sessions at once.
  • Requests from web pages on other origins are refused, and so are DNS-rebinding attempts on a loopback address.
  • Failed logins are rate-limited separately from the local socket, so network attempts can't lock out your CLI.
  • Idle sessions expire after 30 minutes.
  • Requests, tokens, terminal output and typed input are never logged.

Launching Trellis with --no-mcp keeps the server off for that run, whatever the setting says.
