Features

Notifications

Trellis shows on each tab what its panes are doing, so you can leave work running and see at a glance which one needs you. When you're looking elsewhere, it can post a desktop notification too.

Busy bar

A tab's top edge fills and empties while any of its panes is printing output, whether the tab is selected or not. It stops shortly after the output goes quiet. Hover it to see "Printing output".

  • Typing echo doesn't count, and with shell integration neither does output at the prompt.
  • Without integration (for example over SSH), programs that redraw on a timer, such as top or watch, keep the bar on.
  • With Reduce Motion on, the bar is static.

Waiting for input

A tab gets an Input label when a program in it is waiting for you:

  • Password prompts (sudo, ssh, read -s) label the tab for as long as they last, even when it's selected. The pane header says Password.
  • Bells and notifications from a program label the tab only when you aren't looking at that pane.

The label clears when you show and focus the pane, at the shell's next prompt, or when the session ends. Spaces with a waiting pane show a keyboard symbol in the sidebar. Bells at your own prompt, such as a Tab-completion beep, never label a tab.

Progress

Programs that report progress (the Windows Terminal / ConEmu progress sequence) fill the tab's top edge to the percentage. The tab and pane header say it in words too: "50%", "Paused 50%", "Error" or "Working". An error fills red and a pause orange. Progress clears when the program removes it, after 15 seconds without an update, or at the next prompt.

Exit status

With shell integration, a failing command shows a failure symbol with its code, such as "Exit 1", on the tab and pane. It clears when the next command starts. A session that ends shows its exit code in the pane.

Coding agents show their own states, such as Needs you and Done, in place of these labels. See Coding agents.

Desktop notifications

Trellis posts a macOS notification when a program asks for one (iTerm2, rxvt-unicode and kitty notification sequences), but only when you aren't looking at the pane: Trellis isn't in front, or the pane isn't the focused pane of the selected tab.

  • The subtitle says where it came from: Space › Tab, followed by the program or agent name when the title doesn't already say it. Command lines and arguments are never shown.
  • Click a notification to bring Trellis forward on that space, tab and pane.
  • Each pane can post at most 5 notifications every 10 seconds.

macOS asks for permission the first time. Turn notifications off in Settings → Sessions → Desktop notifications; tabs still get their Input label.

Try it: run this, then switch to another app.

sleep 3; printf '\e]9;Build done\a'

When a long command finishes

With shell integration, a command that runs for a while and finishes out of view posts "Command finished", or "Command failed (exit N)", with the program name and how long it ran, for example "make ran for 12 s". Set the threshold in Settings → Sessions → Notify when a command finishes: Off, 5, 10 (the default), 30 or 60 seconds. It's unavailable while desktop notifications are off.

Coding agents

With Settings → Agents → Notify me when an agent needs me or finishes while its pane is out of view on, an agent that needs you or finishes its turn out of view posts a notification too.

Bell

Settings → Appearance → Bell sets what a bell does in a pane: Sound (the default), Visual flash, Sound and flash or Off. Whatever you choose, a bell in a pane you aren't looking at still labels its tab.

Note

Every status is shown with words or symbols as well as color, and VoiceOver reads it with the tab.
