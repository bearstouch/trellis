Features

SSH hosts

Keep the servers you use in a host library and connect to one in a new tab or space. Trellis runs your system ssh, so your config, keys, agent and known hosts work exactly as they do in any other terminal.

How it works

Trellis has no SSH implementation of its own. Each connection runs /usr/bin/ssh inside the pane, with one ssh process per connection.

  • Fields you fill in on a host override your SSH defaults. Fields you leave empty are left to ~/.ssh/config.
  • No shell is involved in building the command, so nothing typed into a host field can run as a command.
  • Host-key checks are never bypassed. Unknown or changed host keys, passphrases and passwords are asked in the pane, as ssh asks them.

Open the host library

Choose File → Hosts…, or search for Hosts in the command palette. The library lists your saved hosts, with a search field to filter them by name or tag.

Add a host

  1. In the host library, choose New Host.
  2. Enter a display name and a destination: either an alias from your SSH config or a hostname.
  3. Optionally set a username, a port (1–65535), an identity file and tags.
  4. Choose Add Host.
FieldNotes
Display nameAny label. Also names the tab or space a connection opens.
DestinationAn alias or a hostname. It can't start with -.
UsernameOptional. Empty means your SSH config decides.
PortOptional, 1–65535.
Identity fileOptional. Trellis stores the path, never the key itself.
TagsUsed for search and filtering.

Edits apply to later connections only. Sessions already running keep the settings they started with.

Import aliases from your SSH config

Choose Discover SSH Aliases… in the host library. Trellis reads the literal Host names in ~/.ssh/config and lets you pick which to save. Each one is saved as an alias, so ssh keeps applying your configuration when you connect.

  • Wildcard patterns and Match blocks don't become hosts.
  • Include files that discovery doesn't follow are labeled. You can still add those aliases by hand.
  • Discovery never runs commands and never changes your SSH config.

Connect

Select a host and choose one of:

  • Connect in New Tab: opens a tab in the current space.
  • Connect in New Space: creates a space named after the host, with one connected tab.
  • Open Remote Workspace: sessions that live on the host and survive disconnects. See Remote workspaces.

The command palette also lists each saved host, so you can connect without opening the library. Save or revert unsaved edits before connecting.

When a connection fails

A pane shows running while the ssh process is alive. That doesn't mean you're logged in; Trellis doesn't guess from screen text. If ssh exits, the pane stays open with its exit status so you can read the error. Trellis never retries on its own: reconnect when you're ready.

Saved passwords

If a host logs in with a password, you can save it in the macOS Keychain. Trellis then answers ssh's password prompt for you, once per connection.

  1. Select the host and enter the password under Password (optional).
  2. Save the host. The field shows Saved in Keychain.
  3. To change it later, choose Replace…. To delete it, choose Remove.
  • A saved password is never shown again. It never appears in the host file, exports, the CLI, the automation API, logs or the pane.
  • Only the first password prompt is answered. Host-key confirmations, key passphrases, one-time codes and any second password prompt are still asked in the pane.
  • Changing the host's destination, username, port or identity file removes the saved password, so it can't be sent to a different server. Renaming or retagging keeps it.
  • Deleting the host deletes its saved password too.

Require Touch ID

Turn on Require Touch ID or Mac password to use to confirm each connection that would use the saved password. If you decline, type the password in the terminal instead. Turning the option off also asks first.

Note

To send the password, Trellis must read it from the Keychain for the moment ssh asks for it. It is passed only to a small bundled helper started by that ssh process, and buffers Trellis owns are cleared afterwards.

Limits

  • There's no field for extra ssh arguments. Put options in ~/.ssh/config and save the host as an alias.
  • SFTP and automatic tmux attachment aren't included.
  • Saved hosts can be moved to another Mac with File → Export Projects & Hosts…. Saved passwords stay in this Mac's Keychain.
