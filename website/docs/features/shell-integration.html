Features

Shell integration

Shell integration lets a local zsh, bash or fish shell tell Trellis its current folder, the command it's running and how that command ended. It's on by default and needs no setup.

How it works

When Trellis starts a supported login shell, it loads a small bundled script alongside your own startup files. Your dotfiles aren't edited, and they still load as usual (.zshrc, .bash_profile, config.fish and the rest).

  • zsh and fish are supported.
  • bash 3.2 and later, including the macOS /bin/bash and Homebrew's bash 5.

Other shells, custom commands and panes connected over SSH start unchanged.

What you get

  • Current folder. The pane header shows the shell's folder. New splits and new tabs start there.
  • Folder restored after relaunch. A stopped shell pane starts again in the last folder it was in.
  • Exit status. After a failing command, the tab and pane show a failure symbol with "Exit 1" (or whatever the code was). It clears when the next command starts.
  • Automatic titles. A tab you haven't renamed shows the running program (vim), or else the folder name (~ at home).
  • Prompt navigation. Edit → Previous Prompt (⌘↑) and Next Prompt (⌘↓) scroll to earlier and later prompts.
  • Quieter busy bar. Output at the prompt never counts as activity. See Notifications.
  • Command-finished alerts. A long command that finishes while you're looking elsewhere posts a desktop notification. See Notifications.
  • Tasks, directory jump and git status. Tasks need it to run, Directory jump learns your folders from it, and the Changes badge uses it to track the focused pane's repository.

Turn it on or off

  • Settings → Sessions → Shell integration turns it on or off. The change applies to sessions you start afterwards.
  • Settings → Sessions → Shell lists the shells installed on your Mac and marks the ones with integration. Other… takes any absolute path, and a note under the picker says whether that shell gets integration.

SSH panes

Trellis installs nothing on remote hosts. If the remote shell already has its own integration (iTerm2's is the most common), Trellis reads what it prints in a saved host's pane or a pane started as ssh, mosh or autossh. The pane header then shows SSH · host:/path, and titles, exit status and command-finished notifications work.

Anything printed in the pane could fake this information, so it's for display only. Trellis never uses a remote folder for file links, new panes or the saved launch folder.

Note

A host you reach by typing ssh inside a local shell isn't detected as remote, and its marks are ignored.

Privacy

  • The command line is never saved, logged, exported or returned by the API. Only the program name is shown, as a title or in a notification.
  • Each session gets a secret that its shell uses to prove its reports are genuine. A program that prints fake reports changes nothing.
  • The current folder is saved only as a local pane's launch folder and, unless you turn it off, in the directory history.

Limits

  • bash reports only the first command of a line, so env | grep x shows as env.
  • With integration off, or in another shell, the folder, titles, exit status, task runs and command-finished alerts aren't available.
