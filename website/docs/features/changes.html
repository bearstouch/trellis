Features

Changes

The Changes view lists what changed in the focused pane's git repository, with lines added and removed. Read a file's diff in a Review tab and stage or unstage it without leaving Trellis.

Open Changes

Click the branch icon in the dock, second after Files, or press ⌥⌘G. The icon's badge shows how many files the focused pane's repository has changed.

The view follows the focused pane: a cd into another repository, or focusing a pane in one, moves it. Changes works for panes on this Mac only; its icon is dimmed for SSH and remote workspace panes.

What it shows

  • Branch: the branch (or detached commit) and how far it's ahead of and behind its upstream, like ↑2 ↓0.
  • Uncommitted: lines added and removed across all changes, and the number of changed files.
  • Filter: type to show only files whose path contains the text.
  • Tree: folders, then files. Each shows its lines added and removed; each file has a status letter and, if staged, a staged mark.

Changes are counted against HEAD, so a file appears once whether its change is staged or not. Untracked files are included, and renames show as a deletion plus an addition. Binary files show "binary" instead of line counts.

Click a folder to fold it; Collapse All folds them all. The view refreshes when you show it, when the pane returns to a prompt, after staging, and when you click Reload. Up to 2,000 files are listed.

Review a diff

Click a file, or select it and press ↩, to open its diff in the space's Review tab, after your terminal tabs. A space has one Review tab; reviewing another file replaces its content.

The diff is unified, with old and new line numbers and +/− marks. The header shows the file, its status, its line counts and its place in the list, like "12 of 17".

The Review tab also has Open in, Reload, and Stage or Unstage. Selecting a terminal tab or pressing Esc keeps the Review tab around so you can come back. While it's shown, Close Pane and Close Tab close the Review tab, never a terminal you can't see. The Review tab is never saved with your workspace.

Diffs over 2 MB or 20,000 lines aren't shown; Trellis offers to open the file instead.

Stage and unstage

Hover or select a row and click Stage to stage the whole file (a deletion too), or Unstage to put its index entry back to HEAD. Your working copy is never touched.

  • A partly staged file offers Stage.
  • Staging a conflicted file asks Mark … as resolved? first, because the file is staged as it is, conflict markers included. Cancel leaves it alone.
  • If git reports an error, Trellis says which file couldn't be staged and nothing else changes.

That's all the view writes to your repository. There's no commit, discard or hunk staging; use git in a pane for those.

Safe in any repository

Reading changes never runs a program the repository configures: git hooks, the fsmonitor, filter drivers, external diff tools and text conversion are all switched off. Submodules are listed only when their commit changed. Staging does run filter drivers, just like git add in a shell, so Git LFS and similar setups store the right content.
