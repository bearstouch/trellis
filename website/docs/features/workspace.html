Features

Spaces, tabs & splits

Spaces in the left sidebar keep each project's sessions together. Every space has its own tab bar, and every tab holds a layout of split panes. Switching never stops a process.

Spaces

A space is one entry in the left sidebar. It's usually what a project becomes when you launch it, but it can also stand alone.

  • Create an empty space with New Space (⌘N) or the + button in the sidebar.
  • Select a space by clicking it, or move through the list with ⌃⌘] and ⌃⌘[.
  • Rename, move or delete it from its context menu: Rename…, Move Up, Move Down and Delete Space….
  • Reorder by dragging a space onto another. An accent bar shows where it will land.

Sessions in other spaces keep running while you work elsewhere. The sidebar marks spaces with activity, exited sessions, and a keyboard symbol for a pane waiting for input. Each space remembers its selected tab and focused pane, so switching back puts you where you were.

Deleting the last space is fine: Trellis shows the welcome screen, where you can create a new one.

Note

Spaces used to be called windows. In Trellis, "window" now means only the macOS window that shows the sidebar.

Collapse the sidebar

Click the sidebar button or choose View → Hide Sidebar (⌃⌘S) to shrink the sidebar to a narrow rail. Each space becomes a square with its initials; the selected one has a border, and activity and exit markers stay visible.

  • Hover a square to see a card of that space's tabs with their live status. Click a tab in the card to jump to it.
  • Right-click a square for the same Rename, Move and Delete actions.

Trellis remembers whether the sidebar is collapsed.

Project spaces and temporary tabs

A space launched from a project shows a folder symbol, and the project's name when it differs from the space's. Tabs the project defines read normally. Any other tab you add there (a new tab, a duplicate, an agent or host tab) is temporary: its title is in italics.

Temporary tabs never change the project. Launching the project again keeps them where they are. If you delete the project, the space keeps all its tabs and none are temporary any more.

Tabs

The selected space's tab bar sits above its panes. Each space keeps its own tab order and selection.

  • New tab: ⌘T or the + button at the end of the tab bar.
  • Rename: double-click the label, or choose Rename… from its context menu. ↩ saves, Esc cancels, and an empty name keeps the old one. Renaming never restarts a session.
  • Reorder: drag a tab along the bar, or use Move Left and Move Right in its context menu.
  • Duplicate: Duplicate Tab copies the layout and launch settings into new sessions. No output or typed input is copied.
  • Close: ⇧⌘W or Close Tab….

A tab you haven't renamed takes an automatic title from the running program or the current folder when shell integration is on.

Color labels

Right-click a tab and pick a Color: red, orange, yellow, green, blue, purple or gray. A labeled tab gets a colored stripe along its top edge and a light tint. Choose None to remove it. Hover the stripe to see the color name; VoiceOver reads it with the tab.

Tab status

Tabs show what their panes are doing, in words and symbols as well as color. See Notifications for the busy bar, the Input label, progress and exit status.

Splits

Split any pane, as often as you like, to build nested layouts.

  • Split Left/Right puts a new pane beside the focused one.
  • Split Top/Bottom puts a new pane below it.
  • Drag a divider to resize, or use the keyboard. A pane never shrinks below 20 columns by 5 rows.
  • Maximize / Restore Pane temporarily fills the tab with the focused pane, then puts the layout back exactly as it was.

With shell integration, a new split or tab starts in the focused shell's current folder.

When a tab shows more than one pane, the focused pane's header gets an accent line and tint, and the other panes are slightly dimmed. Nothing is dimmed when the window is inactive or Increase Contrast is on.

Closing a pane lets its neighbor fill the space. Closing a tab's last pane closes the tab, and closing a space's last tab closes the space.

If the window gets too small for a layout, Trellis keeps it at its minimum size and lets you scroll. Panes are never removed or squeezed below their minimum.

Closing panes, the window and quitting

Closing a pane, tab or space with running sessions asks first, with one confirmation that lists every affected pane.

Closing the Trellis window only hides it. Sessions keep running, and clicking the Dock icon brings the window back.

Quitting with ⌘Q keeps your sessions running by default: they come back, still running, the next time you open Trellis. To end them on quit instead, turn on Settings → Sessions → Stop sessions when Trellis quits. With that on:

  • Quitting asks before ending running sessions.
  • Closing the window while sessions are live asks once whether to end them. Your spaces, tabs and splits stay as stopped panes either way.

Spaces, tabs, names and splits are always saved. Stopped panes come back stopped; Trellis never reruns a command or replays what you typed. Press Restart in a stopped pane to start it again.

Export projects and hosts

File → Export Projects & Hosts… writes your project library and saved hosts to one file; File → Import Projects & Hosts… reviews such a file before adding anything. Spaces themselves aren't exported, since they're what projects become once launched. See Projects.
