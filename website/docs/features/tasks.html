Features

Tasks

Tasks are a repository's named build, test and run commands, checked in as .trellis/launch.json. Trellis lists them for the focused pane's project and types the one you pick into its shell.

Open the Tasks view

Click the checklist icon in the right sidebar's dock, or press ⌥⌘T. The view shows the project's name and folder, its tasks with their exact command lines, and an Edit launch.json (or Create launch.json) button.

The project is the nearest folder at or above the pane's current folder that contains .trellis or .git. Your home folder and / never count as a project. Tasks work in local panes and in remote workspace panes; the view is unavailable for plain SSH panes.

The view reads the file again when you open it, focus another pane, or click Reload.

Write launch.json

This is the .trellis/launch.json in the Trellis repository itself:

{
  "version": 1,
  "tasks": [
    {
      "name": "build",
      "command": "swift build",
      "group": "build"
    },
    {
      "name": "test",
      "command": "swift test",
      "group": "test"
    },
    {
      "name": "lint",
      "command": "swift format lint --strict -r Sources Tests",
      "group": "test"
    },
    {
      "name": "format",
      "command": "swift format -i -r Sources Tests"
    },
    {
      "name": "run fixture",
      "command": "swift run Trellis --fixture",
      "group": "run"
    }
  ]
}

Fields

FieldRules
versionMust be 1.
tasksUp to 100 tasks.
envOptional variables for every task in the file.
nameRequired, 1–100 characters, unique in the file.
commandRequired. One shell line, up to 4,096 characters.
cwdOptional folder relative to the project folder. No absolute paths, ~ or ...
groupOptional: build, test or run, shown next to the task.
env (task)Optional variables for this task; they win over the file's for the same name.

Variable values are literal: $HOME arrives as the text $HOME. Unknown fields are errors, and a file with any error runs nothing; the view names the task that's wrong. Files are limited to 64 KB.

A task with variables:

{
  "name": "test UI",
  "command": "swift test --filter TrellisUITests",
  "group": "test",
  "env": { "TRELLIS_TEST_VERBOSE": "1" }
}

Detected tasks

Trellis also finds common tasks in the project folder without running anything: package.json scripts (npm, pnpm, yarn or bun), Make targets, CMake, SwiftPM, Python (pytest, unittest, tox) and Cargo. Run one directly, or click + to add it to launch.json, which is created if it doesn't exist.

Run and stop a task

  1. Focus a shell pane in the project, idle at its prompt.
  2. Click Run next to a task.
  3. The first time you run a task from a new or changed launch.json, review every task's name, folder, variables and command, then click Trust and Run.

Trellis clears anything half-typed at the prompt and types one line, followed by Return: the command, preceded by a cd into the task's folder when the shell isn't already there. The cd stays in effect afterwards, like any command you type. Tasks with variables run in a new, non-interactive instance of your shell, so your aliases and functions aren't available to them.

The view shows Running: name with the elapsed time, then done, exit N or ended. The dock's Tasks badge counts running tasks across all panes.

Stop sends ⌃C. If the task is still running two seconds later, the button becomes Force Stop, which sends ⌃\. The shell and pane stay open.

Note

Run needs shell integration. Trellis only types into a shell that has reported it's idle at its prompt, so a task never lands inside an editor or a running program.

To write a multi-line script and save it as a task, use the scratchpad.

Trust and safety

  • launch.json comes with the repository, so anyone who can change it can change what Run types. That's why each new version needs your review once. Changing a single byte asks again.
  • Variables are typed into the terminal along with the command, so they appear on screen and in your shell history. Don't put secrets in launch.json.
  • Trellis never logs the typed line.

Limits

  • Stop can't end a program that ignores ⌃C and ⌃\; restart the pane instead.
  • Clearing a half-typed line works with emacs-style line editing. In vi mode, or partway through a multi-line command, finish or cancel what's at the prompt first.
  • Detection looks only at the project root, not subfolders or monorepo packages.
