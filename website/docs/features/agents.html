Coding agents Preview

Run Claude Code, Codex and pi in their own panes, in your project's folder, and see on each tab whether an agent is working, needs you or is done. Switch spaces freely: the tab tells you when to come back.

Preview

Coding agents shipped in Trellis 1.1.0 as a preview. The basics are tested, but some behavior may still change.

Open an agent

  1. Focus the pane whose folder you want the agent to work in.
  2. Click the sparkles icon in the dock, or press ⌥⌘A, to show the Agents view of the right sidebar.
  3. Choose where it opens: New Tab (the default), This Tab or Split.
  4. Click the play button next to the agent.

The agent starts in the focused pane's folder, on the same machine. In a remote workspace it runs on that space's host.

  • New Tab opens a tab in the same space and selects it.
  • Split opens the agent to the right of the focused pane.
  • This Tab runs the agent in the focused pane itself. It's offered only while no agent runs in that tab. If the pane's shell is idle at its prompt, Trellis asks Replace this shell with… first; background jobs end with the shell. If a command is running, nothing is ended and Trellis suggests a new tab instead.

⌥-click the play button to use a split instead of a new tab (or a new tab instead of a split). From the keyboard, open the command palette and choose Launch Agent…: ↩ opens a new tab, ⌥↩ a split.

The circular-arrow button next to an agent opens it with its Resume arguments, continuing its last conversation.

See what an agent is doing

While an agent runs, its tab shows the agent's icon in place of the terminal icon.

  • Working: a light moves along the tab's top edge and the icon breathes. With Reduce Motion on, the edge shows a steady bar instead.
  • Needs you: the agent is waiting for an answer or a permission.
  • Done: the agent finished its turn. Shown until you've seen the tab.
  • Error: the agent's turn failed.

States are shown in words with a symbol, never by color alone. With several agents in one tab, the most urgent wins. The Agents icon in the dock counts the agent panes that need you, in every space.

The Running list in the Agents view shows every agent in every space, with its tab, space and state. Click a row to go to that pane.

How it knows

Trellis passes each agent a small hook on its command line that reports only state changes, such as "working" or "needs input". Nothing from your conversation reaches Trellis, and Trellis never edits your agent configuration. Where an agent has no hook for something, Trellis also uses the terminal's own signals: a bell or notification means needs you, and for Codex pressing ↩ means working.

Agents typed in a shell

You can also just type claude, codex or pi at a prompt. With shell integration on zsh, bash or fish, the tab shows the agent's icon and titles itself after the agent while it runs, and it's listed under Running marked "in a shell".

With Settings → Agents → Connect agents typed in a shell on (the default), local shells also get live state for typed agents: working, needs you, done and notifications. Trellis does this with a shell function named after each agent, defined only in that pane's shell.

  • A function or alias of the same name you define yourself wins.
  • Run command claude (or command pi, command codex) to skip the wiring.
  • Changing the setting applies to shells started afterwards.
  • Remote workspace and SSH panes don't get live state for typed agents. Open the agent from the Agents view instead.

Only the plain command is recognised: npx claude or cd x && claude isn't. Another program with the same name as an agent (such as a different pi) shows that agent's icon too; run it with command pi or turn the setting off if it rejects the extra arguments.

Install a missing agent

If an agent isn't installed where the pane runs, Trellis shows a sheet with the vendor's own install command, what it needs on PATH and the vendor's page. Install and Launch runs the installer in the pane, visibly and without sudo, then starts the agent. Cancel runs nothing. Trellis never bundles or uploads an agent.

After a relaunch

Agent panes are saved with your workspace (only the agent, host and folder, never the command line). If an agent pane was stopped when Trellis relaunches, it shows Start with the agent's name, and Resume Last Conversation; nothing runs by itself. An agent that exited shows Restart and Resume.

Projects can name an agent per pane, so launching a project opens its agents too.

Notifications

With desktop notifications allowed and Settings → Agents → Notify me when an agent needs me or finishes while its pane is out of view on, Trellis posts a notification such as "Claude Code needs you" or "Claude Code finished", with the space and tab as the subtitle. See Notifications.

Add your own agent

Each agent is a small JSON file named <id>.agent.json. Click Add Agent Definition… in the Agents view, or Settings → Agents → Reveal Agents Folder, and add a file:

{
  "version": 1,
  "id": "aider",
  "name": "Aider",
  "executable": "aider",
  "arguments": [],
  "resumeArguments": ["--restore-chat-history"],
  "integration": "none",
  "icon": { "monogram": "A" },
  "install": {
    "darwin": { "command": "python3 -m pip install --user aider-install && aider-install", "requires": ["python3"] }
  },
  "homepage": "https://aider.chat"
}
id
Lower-case letters, digits and -; must match the file name. IDs starting with trellis- are reserved.
executable
A command name on your login shell's PATH, or an absolute path.
arguments, resumeArguments
Single-line arguments for a normal start and for Resume.
integration
Use none for your own agents: the tab then follows the terminal's signals only.
icon
{"symbol": "…"} (an SF Symbol), {"monogram": "A"} (one or two characters) or {"image": "aider.svg"} (SVG, PNG or PDF next to the file, up to 32 KB).
install
Per platform (darwin, linux): a one-line install command and the programs it needs.

Click Reload in Settings → Agents to read the folder again. Files that can't be used are listed under Files that couldn't be used with the reason.

Warning

A definition can name any install command. Only add definitions you trust.

Known limits

  • Claude Code needs a version that supports --settings and the PermissionRequest hook for live state.
  • Codex reports only finished turns. "Working" comes from pressing ↩, so ↩ in one of its menus can show Working until the turn ends.
  • pi has no approvals, so it never reports Needs you by itself.
  • Extra arguments per built-in agent aren't configurable yet; add your own definition instead.
  • Automation can't start or list agents yet.
