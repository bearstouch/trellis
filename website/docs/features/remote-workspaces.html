Remote workspaces Preview

A remote workspace is a space bound to a saved SSH host. Every tab and split in it runs a shell on that host, and those shells keep running when you quit Trellis, your Mac sleeps or the network drops. When the link comes back, Trellis re-attaches with the output you missed.

Preview

Remote workspaces are new and still being qualified on real servers. Expect rough edges, and keep anything critical in tmux or similar until you trust it.

How it works

  • Trellis installs a small helper on the host, in ~/.trellis. It owns your remote shells, so they don't depend on the ssh connection.
  • Trellis opens one ssh connection per host using your system ssh, and every space on that host shares it. You authenticate once, not once per pane.
  • Nothing listens on the network on either side. SSH is the only transport and the only authentication.
  • The host can run Linux (x86_64, aarch64) or macOS (Apple silicon, Intel). Trellis itself runs on your Mac.

Open a remote workspace

  1. Save the host in File → Hosts… if you haven't already.
  2. Select it and choose Open Remote Workspace, or pick Open Remote Workspace: host in the command palette.
  3. The first time, Trellis shows the host, its OS and architecture, the install path and the helper's size. Choose to install, or decline and nothing is written.
  4. A new space named after the host opens with one tab. The sidebar shows the host and the link state.

New tabs (⌘T), splits (⌘D) and duplicates in that space run on the same host, in the directory of the pane you started from. If that directory isn't known or no longer exists, the shell starts in your remote home.

You can also launch a project on a saved host; it opens as a remote workspace in the project's folder on that host.

The connection console

ssh's own questions appear in a connection console: host-key confirmations, passwords, passphrases and one-time codes. Answer them there. A changed host key shows ssh's warning and the link fails; Trellis never bypasses it. A saved password is used as it is for SSH panes.

Link states

The link has its own state, shown in words with a symbol in the sidebar, pane headers and the bottom bar:

StateMeaning
Connectingssh is starting.
Needs inputssh is waiting for you in the connection console.
ConnectedPanes are live.
ReconnectingThe link dropped and Trellis is retrying. Remote sessions keep running.
OfflineYour Mac has no network. Retries pause until it returns.
FailedThe link couldn't be made. Open the console to see why.

Reconnecting

  • A lost link is noticed within about 30 seconds, and right away after wake or a network change.
  • Trellis retries on its own, backing off from 1 second up to a minute. Retry Now is always available.
  • While reconnecting, typing is refused, never queued. The first refused keystroke shows Not sent: reconnecting. Tabs with panes on that host show a red indicator until they're back.
  • Output produced during the outage appears once when you're back, up to 4 MiB per session. Beyond that the pane shows the most recent 4 MiB.
  • If logging in needs your input, automatic retries stop and the pane offers Reconnect…, which opens the console.

Tip

Automatic reconnect needs non-interactive login: a key or an ssh agent. Hosts that log in with a password, even a saved one, always stop and wait for Reconnect… after a drop.

Quitting and relaunching

  • Quitting Trellis or closing the window detaches remote sessions without signaling them, whatever your session settings say.
  • After relaunch, restored panes re-attach once the host is connected. A session that ended meanwhile shows its last output and its exit status.
  • If the host has sessions that no pane claims, Trellis offers Stop Them or Leave Running, once per host.
  • Closing a pane, tab or space ends its remote sessions, after the usual confirmation.

Manage the helper

Each host in the host library has a Remote helper section with a status line, such as "Installed, up to date (Linux aarch64)", and these actions:

  • Check Helper Status: connects and reports what's installed.
  • Install Trellis Helper… or Update Helper…: uploads the helper bundled with this Trellis version.
  • Remove Helper…: deletes the helper from the host. This affects every Mac using that host, and asks first if your sessions there are still running.
  • Install helper automatically when opening a remote workspace: off by default. When on, later versions install without asking.

The helper needs no administrator rights. Every upload is checked against a digest bundled with the app before it's used, and nothing outside ~/.trellis on the host is written. After a Trellis update, a running older helper keeps its sessions until they end.

Tasks on the host

The Tasks view works in remote panes with shell integration, listing the host's launch.json and detected tasks. Add to launch.json isn't available for remote panes.

Limits

  • Remote sessions survive what the host survives. A reboot, a crash of the helper, or a login policy that kills user processes on logout ends them. Trellis warns when it detects such a policy.
  • Shells started before a reconnect keep the old agent socket, so ssh agent forwarding inside them stops working after a reconnect, as with tmux.
  • Only one Mac can attach a given set of sessions. Two Macs on the same host each see only their own.
  • Remote file links, editing remote task files and file transfer aren't included.
  • Automation can read and drive remote sessions but can't create remote workspaces yet.
  • Shell integration on the host works for zsh, bash and fish. Other shells start plain.
