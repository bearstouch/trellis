Features

Projects

A project is a layout you define once and launch whenever you need it: its tabs, splits and panes, each pane's folder and command, and the git repositories it's made of. Launch it on this Mac or on any saved SSH host, and Trellis clones what's missing and opens it as a space.

Open the library

Click Projects at the bottom of the sidebar, or choose File → Projects… (⌘O). The library opens in its own window: a searchable list on the left, the selected project's editor on the right. Search matches names, notes and repository URLs.

Projects live in Trellis's own settings, not in a repository, so one definition can set up your laptop, a build server or a fresh VM.

Create a project

  • New Project starts with one tab and one pane.
  • New from Space… captures an open space: its tabs, titles, colors and splits. Commands are never captured, and SSH or program panes become plain shells.
  • Import JSON… reads a project file. It opens in the editor, unsaved, so you can check its commands and repositories first.

Edit a project

The editor shows the project's name, notes and repository, and an outline of its tabs, splits and panes.

  • Select a tab to set its title, color and repository.
  • Select a pane to set its title, folder, command and repository, and whether it Runs a shell or a coding agent.
  • Change the outline with Add Tab, Split Right, Split Down and Remove; reorder tabs with Move Up and Move Down.
  • Save stores the project. Delete… asks first.

Every field is checked as you type, and Save stays disabled until the problems are fixed. Leaving a project with unsaved changes asks whether to save or discard them.

What goes in a pane

  • Folder: relative to the project folder you pick at launch. Leave it empty for the project folder itself.
  • Command: one line, typed into the pane's shell at its first prompt.
  • Repository: an https://, ssh:// or user@host:path URL, with an optional branch. The pane's folder becomes a checkout of it.

Edit as JSON

Switch the editor from Form to JSON to edit the project as text. Validate (⌥⌘V) lists each problem with its tab or pane; Save is ⌥⌘S. Text that doesn't validate can't be saved. Export JSON… writes the selected project to a file.

{
  "name": "Web shop",
  "repository": { "url": "git@github.com:acme/shop.git" },
  "tabs": [
    {
      "title": "Dev",
      "color": "green",
      "root": {
        "type": "split", "axis": "x", "ratio": 0.5,
        "children": [
          { "type": "pane", "command": "npm run dev" },
          { "type": "pane", "directory": "api" }
        ]
      }
    }
  ]
}

Launch a project

  1. Select the project and click Launch….
  2. Choose the target: This Mac or a saved host. Then choose the project folder there (an absolute path on this Mac, a path relative to your home on a host). Both are prefilled from the last launch.
  3. Review what will happen: whether the folder exists, which repositories are already cloned, which will be cloned, and the tabs, panes and commands that will open.
  4. Click Open, or Set Up & Open when something is missing.

Setup runs in a terminal on the target, using that machine's own git and credentials. Answer any host-key, passphrase or password prompts there; Trellis never stores or types credentials. If a step fails, choose Retry, Open Anyway or Cancel.

The new space is named after the project, and each command runs once at its pane's first prompt. You can also launch from the command palette with Launch Project….

Launching again

Launching the same project to the same target and folder selects its space and brings it up to date: new tabs and panes are added, and changed titles, colors and ratios applied. Nothing is removed or restarted, and no command runs again. Tabs you added yourself stay as temporary tabs.

The same project on another target or folder opens a separate space. Commands never rerun when Trellis restores a workspace.

Git status

For a local or remote-workspace shell inside a git repository, Trellis tracks the branch, the number of uncommitted changes and how far you are ahead of or behind upstream. The Changes badge in the dock counts the focused pane's changes. This needs shell integration, and git is never allowed to run hooks, filters or fetches for it.

Back up and move projects

File → Export Projects & Hosts… writes every project and saved host to one file. File → Import Projects & Hosts… checks the whole file and shows a summary before adding anything. A project named like one you already have is added as "… (imported)", never over yours. Nothing opens or starts on import.

Trust and safety

  • You write a project's commands yourself, so launching runs them without a further review. They run in the target's login shell with your permissions.
  • Setup only creates folders, clones into empty places or initializes the project folder in place. It never deletes, resets or overwrites files.
  • Commands are never logged or saved with the workspace.
