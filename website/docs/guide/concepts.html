User guide

Concepts

Trellis arranges your terminals in a simple hierarchy: spaces hold tabs, tabs hold splits of panes, and each pane runs one session. Once this clicks, everything else follows.

The hierarchy

Space
A named item in the left sidebar that holds an ordered list of tabs. A space is usually one project, loaded from the Projects library, plus any temporary tabs you open in it. A space can also be a remote workspace whose sessions run on another host.
Tab
A named container in a space's tab bar. Each tab holds one layout of panes and remembers which pane was focused. Tabs can be renamed and color-labeled.
Split
A division of a tab into two parts, either left/right or top/bottom. Splits nest, so any pane can be split again. Drag a divider, or use ⌥⇧⌘ + arrow keys, to resize.
Pane
One visible terminal inside a tab. Every pane owns exactly one session.
Session
The process running in a pane: usually your login shell, an SSH connection to a saved host, or a task's command.

A few rules keep this tidy:

  • A space always has at least one tab, and a tab at least one pane. Closing the last pane closes the tab; closing the last tab closes the space.
  • When a pane closes, its neighbor takes the space it used.
  • You can have no spaces at all. Trellis then shows a welcome screen.
  • Selecting another space or tab never stops anything. Background sessions keep running and their tabs show when they're busy or waiting for you.

Projects and temporary tabs

A project is a saved recipe: its tabs, splits, folders, startup commands and git repositories. Launching a project creates a space from it, on this Mac or on a saved host, and clones repositories that are missing.

Tabs you open in a project's space that the project doesn't define are temporary tabs. They're shown in italics and never change the saved project. See Projects.

Session states

Each pane shows its session's state in words, not just color:

StateWhat it means
StoppedThe pane has a layout but no process yet. Press Start Session in the pane to run it.
RunningThe process is alive.
ExitedThe process ended. The pane stays open with its output and exit code until you restart or close it.
FailedThe process couldn't start, for example because its folder doesn't exist. The pane says why.

Restart runs a fresh session in the same pane. Trellis never replays what you typed before.

Sessions keep running

By default, sessions run in a small background helper that Trellis starts for you. That means:

  • Quit (⌘Q) and your sessions keep running. Reopen Trellis and they come back in their panes, with their recent output.
  • Close the window and Trellis just hides it. Click the Dock icon to bring it back.
  • If Trellis stops unexpectedly, sessions survive and reconnect on the next launch.
  • Logging out or restarting your Mac ends them.

Prefer a clean slate? Turn on Settings → Sessions → Stop sessions when Trellis quits. Quitting then asks to end running sessions, and your spaces, tabs and splits come back stopped next time, ready to start again.

Note

Trellis saves the layout, never the contents of your terminal or what you type. If you want each pane's last output after a relaunch, turn on Restore scrollback after quit in Settings → Sessions. It's saved unencrypted, with secrets removed on a best-effort basis.

Closing panes, tabs and spaces

  • ⌘W closes the focused pane, and ⇧⌘W closes the whole tab.
  • If anything is still running, Trellis asks first, in one dialog that lists every pane involved.
  • Trellis then asks the processes to end. If one is still alive after two seconds, you get an explicit Force option. Nothing is killed without you choosing it.

One window

Trellis has a single main window: spaces replace the stack of terminal windows you might use elsewhere.

Automation in one sentence

Everything you can do with the mouse and keyboard goes through the same internal commands that the trellis CLI, the automation API and the MCP server use, so scripts and agents see the same spaces, tabs and panes you do, with the access you grant them.
